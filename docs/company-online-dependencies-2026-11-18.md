## 1. 启动检查：远程列表可以导致客户端退出

- `client/electron/main.cjs:22` 定义 `https://analytics.agnet.top/ip-blocks`。
- `checkBlockedIpAfterStartup()`（同文件第 34 行）在启动后异步 GET，5 秒超时。只在返回 `code=0`、有效 `clientIp` 和列表时匹配；网络失败、无效响应不退出。
- 命中时第 45 行直接 `process.exit(0)`，不走正常 `app.quit()` 和退出前服务关闭链路，也没有用户提示。任务运行过程中若此请求才返回，仍可能退出。启动调用位于第 529 行。
- Worker `routes/ipBlocks.js` 根据请求取公网出口，返回列表；客户端没有上传招标正文或 API Key，也没有逐个上传局域网主机地址。
- **客户端退出与服务器封禁是两件事**：`analytics/worker/src/index.js:95` 仍对命中 IP 的公共接口返回 204。即使未来调整客户端退出，公司出口被服务端封禁时，原服务器上的组件、插件、模型信息和统计仍可能不可用，不能声称调整客户端即可恢复全部服务。
- 管理端封禁还关联统计客户端删除/解除操作（`analyticsStatsStore.js`）。后续不得把这些统计逻辑一起删除或绕过。

## 2. 插件：人工分发主程序不等于插件不更新

- `pluginService.cjs:7` 的目录地址是 `https://analytics.agnet.top/plugins`；列表含实际包 `releaseUrl` 和图标 `iconUrl`。当前实际包在 `openbidkit-oss.agnet.top`，图标在 `raw.githubusercontent.com`。
- 插件页进入/可见时加载列表；Main 缓存非空目录 5 分钟。请求没有显式总超时；异常后 IPC 会返回本地已安装插件，但连接悬挂时不能保证立即回退。
- `UpdateNotifier.tsx:123` 启动检查、每 30 分钟调用 `window.yibiao.checkUpdate()`。`ipc/index.cjs:674` 在返回主程序“更新停用”之前已调用 `checkPluginUpdates()`。因此原作者插件目录仍被周期访问。
- 查询不等于自动安装：有新版本时显示提示，由用户点击升级才执行 `updateAllAvailablePlugins()`。手工插件页升级也保留。
- 线上安装成功向 `/plugins/download` POST `{ id }`，用于下载次数统计；该能力不能随来源改造丢失。
- `pluginService.cjs:444` 已有离线 ZIP 安装/同 ID 覆盖升级，可保留启用状态和配置；UI 已提供“离线安装”。已启用插件从本地加载 `main.cjs`，加载本身不依赖市场响应，但插件内部可能自行联网，须单独核对插件源代码。
- 插件可以通过宿主上下文读工作区、发起功能调用，品牌和远程链接也可能在插件包内；修改宿主 Logo 不会同步修改“易标桌宠”。本轮只读了市场元数据，没有安装、启用或执行远程插件。

## 3. OCR：区分安装依赖、运行依赖与 Word 助手

- `dependencyService.cjs:7` 默认 `https://analytics.agnet.top/dependencies`；已有环境变量 `YIBIAO_DEPENDENCY_API_URL` 可覆盖。地址可覆盖不等于公司接口和安装包已具备。
- 双层 PDF 页面进入后查询 `ocr-v1` 状态；元数据请求 15 秒超时。已安装记录与目录保存在公司独立 userData 下，查询失败仍返回已安装状态。
- 下载地址来自服务器 `downloadUrl`，实际 ZIP 在作者对象存储。安装完成 POST `/dependencies/download`，内容为组件 ID 和平台，下载计数继续保留。
- 当前没有通用的组件 ZIP 离线导入入口；插件的离线安装不能直接当作 OCR 离线安装。
- 转换时从本机读取已安装的 OCR 包；OCR 在隐藏窗口加载本地 WASM/模型，不需要把页面上传作者服务器。
- 没安装 OCR 时仍可转换：Word 文字层可保留，图片里的文字不能搜索/复制，并有提醒。仅导出图片不使用 OCR；页面初始化仍会查询组件状态。
- Word/WPS/LibreOffice 是本机 Office 转换后端；Open XML 助手是已随包准备的另一项依赖。不要把 OCR 服务器迁移当成上轮模板预览修复的替代方案。

## 4. 模型信息：没有接管员工的 AI 请求

- `aiService.cjs:2818` 的 `getModelInfo()` GET `/model-info?modelName=...`，只带模型名，不携带员工 Key、Base URL、招标材料或生成正文；网络服务自然仍可看到请求出口。
- 触发入口是设置页“自动填充高级参数”，不是正文生成每次请求的前置步骤。未查到/失败时保留手工设置；返回值先填当前表单，用户保存才写配置。
- 填充范围包括上下文/输出上限、并发、普通/流式请求、多模态、温度支持和推理档位。作者 Worker 还支持管理员覆盖这些参数，因此不只是不可编辑的第三方模型介绍。
- Worker 从 `https://models.dev/api.json` 同步到 KV，Cron 为 UTC 20:00（北京时间次日 04:00）；客户端本身没有这份离线索引。`getModelInfo()` 当前无显式总超时，本轮不顺带修改。
- **“获取模型列表”是另一条链路**：`aiService.cjs:2774` 请求员工配置服务商的 `/models` 并使用其 Key；正文/生图也走各自配置的服务商。不能把模型列表请求误改到公司模型信息缓存。

## 6. 当前保留的外联能力

- 普通 `/track`：Renderer 页面/功能/资源点击，Main 的模型使用量与 Agent 成败等。使用持久客户端 ID，字段含模型名、服务商域名、Token 用量等，不是纯粹无标识的页面计数；业务正文和 Key 不应进入该链路。作者 Worker 可获知请求 IP。当前项目标识仍是 `yibiao-client`。
- 员工配置的文本/生图服务、MinerU、可选 Parallel Search：属于功能调用，按选择发送完成任务所需内容；不能当作作者推广地址一刀切删除。ComfyUI 和 Agent Proxy 的环回地址是本机服务。
- Markdown 的远程图片、资源/插件图标、下载跳转等：实际目标可来自内容和服务器响应；仅换一个 `analytics.agnet.top` 常量不足以完全迁移。
- 当前“必须联网服务”注册表为空，只表示没有登记强制 Ping 前置条件，不表示软件所有功能都可离线。

1. 启动策略：用合成服务分别返回未命中/命中/断网，验证公司版任务与退出行为；普通统计继续采集，服务端封禁与聚合测试保持。
