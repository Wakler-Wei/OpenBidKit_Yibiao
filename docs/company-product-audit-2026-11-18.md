## 2. 结论

可以改造成公司品牌产品，但工作量超出“换 Logo 和几个链接”。需要同时接管：产品身份、发布更新、在线运营服务、授权体系、模型接入、数据去向、用户支持及升级迁移。

项目已经有可复用的运营后台：`analytics/worker` 与 `analytics/dashboard`。它能管理公告、更新日志、广告、资源、插件、依赖、许可证和统计等；它不是给所有客户端统一配置第三方模型 Key 的后台。

日常模型 Key 仍由客户端设置页保存在本机。作者“官方 API”的账户、充值、余额、开票和模型路由依赖另一个远程服务，本仓库内未发现该服务端的完整实现。公司若要提供同类账户与计费能力，需要另行接入或建设，不能只把域名替换成公司域名。

建议第一阶段保留现有标书业务能力，优先完成公司独立身份、独立更新、运营后台迁移和外联接管；账户计费是否建设，单独决策。

### 3.1 启动 IP 封禁的实际代码

`client/electron/main.cjs:14` 定义 `https://analytics.agnet.top/ip-blocks`。`checkBlockedIpAfterStartup()` 在启动后调用，读取响应中的出口 IP 和封禁列表，命中时执行 `process.exit(0)`；网络失败则忽略。调用点在同文件约第 521 行。

这是实际存在的启动行为，不是根据域名推测。迁移方案应保留公司需要的统计能力，不以删除埋点代替服务接管。

### 3.2 Agent 失败诊断的实际数据范围

入口为 `client/electron/services/agentService.cjs:665`，实现为 `services/agent/agentErrorReporter.cjs` 与 `agentErrorReportProcess.cjs`。

上传有条件：不是预期取消、具备许可证及客户端身份、接收端允许对应版本等。Worker 文档说明接收默认关闭，并要求指定精确版本；不能据此认定每次失败都会上传。

一旦满足条件，诊断包包含错误链、任务与 Prompt、系统信息、本地路径、配置的脱敏副本，以及失败任务工作区的文件内容。代码会清除已配置密钥和常见认证信息，但这种处理不等于删除招标文件、生成正文或企业资料。

因此需修正此前“业务内容不会发到作者服务器”的过宽表述：普通 `/track` 与独立 `/agent-errors` 是两条不同的数据链路。公司版应在保留诊断能力的前提下，明确采集范围、触发策略、接收方与告知文案。

## 6. 模型与账户改造的边界

### 6.1 现状

`configStore.cjs:205` 默认选择 `official` 文本服务商；`:221` 默认选择 `atomgit` 更新渠道。Renderer 设置页也有服务商默认档案，需要两端同步修改。

API Key、模型名、Base URL 等保存在本机 `user_config.json`；`configStore.cjs:569` 将配置直接写成 JSON。公司级共享的上游密钥不能靠打进安装包来实现保密。

`officialAccountService` 不只是一个地址常量：它处理匿名身份、邮箱登录、Token 刷新、API Key、充值二维码、订单、消费记录和发票。`electron/ipc/index.cjs:531` 启动服务；UI、Main、preload 和 IPC 类型都有配套接口。

官方生图从文本官方档案读取共用 Key，与文本共用余额，且使用固定模型标识 `IMAGE_GENERATION`；仅替换为任意 OpenAI 地址并不能保证兼容。

### 6.2 两种待选方案

| 方案 | 需要交付 | 适用情况 |
|---|---|---|
| 用户／公司管理员在各客户端配置模型 | 保留现有第三方与自定义服务商；确定公司默认模型配置；确认后调整原官方入口和启动调用 | 先落地内部工具或首个公司版本，范围较小 |
| 公司提供统一账户和额度 | 公司 AI 网关、身份、Key 签发、额度／计量；按需要加入充值、订单、开票与多设备关联；客户端协议适配 | 面向客户提供统一运营和收费能力 |

统一账户不是品牌改造的附带小修改；应单列项目范围。公司员工 SSO、多人共享知识库、组织管理、审批与团队权限，当前也不能视为已有企业能力，只有明确需要时再立项。

## 7. 更新与发布：必须作为一条链路修改

1. 公司维护独立应用身份、版本号及发布仓库。
2. 修改 `package.json` 的 publish 与安装包命名，同时处理 Release workflow 的 MSI 覆盖项。
3. 修改 `updateService.cjs` 的 GitHub、Cloudflare、AtomGit 地址、默认渠道、产物查找和旧包清理匹配。
4. 配置公司 GitHub Actions 的构建证明私钥；现有 workflow 缺少 `YIBIAO_LICENSE_PRIVATE_KEY_JWK` 会直接失败。
5. 配置公司对象存储发布参数 `R2_*`，处理 `.github/scripts/publish-r2-release.mjs:180` 中的 `Yibiao-` 文件名匹配。
6. 决定是否使用 AtomGit／Gitee 镜像，配套迁移 `.github/workflows/sync-mirrors.yml`、`sync-releases.yml` 及手动下载／runner 脚本。
7. 更新关于页、授权提示、通知兜底链接的下载入口，避免失败时仍跳回作者仓库。
8. 实测“安装公司旧版 → 检查更新 → 下载公司新版 → 安装 → 工作数据正常”。

不能因为代码 fork 已同步，就认为作者的 Release 文件、Cloudflare 资源、发布权限、Actions Secrets 或支付账户也已转移。普通安装包和源码仓库应分别管理。

构建证明签名与 Windows/macOS 操作系统代码签名是两件事。现有流程有构建证明，但未配置操作系统代码签名；面向客户发行时是否申请证书，应列为独立发布决策。

## 8. 运营后台与云资源接管

| 模块 | 现有能力 | 公司需要准备 |
|---|---|---|
| API Worker | 统计、公告、版本日志、资源、插件、依赖、授权、诊断、IP／版本管理等 | 公司域名、部署环境、管理员配置、初始化内容 |
| Dashboard | 上述能力的管理界面 | 改 API 地址、项目标识、显示品牌、访问方式 |
| Analytics Engine | 原始采集和统计查询 | 公司 dataset 与查询权限 |
| D1 | 统计和资源两类数据库 | 公司数据库、迁移执行、备份和管理流程 |
| KV | 公告／系统设置／模型等缓存与配置 | 公司 namespace 与初始化记录 |
| R2 | 发布包、插件、组件、图片、失败诊断 | 公司 bucket、公开域名、生命周期、容量策略 |
| Cron | 每日聚合、模型信息同步等 | 保留统计能力与定时任务，配置相应资源计划 |
| 帮助站 | wiki 文档与个人打赏接口位于另一个站点 | 公司帮助文档、问题反馈和客服入口；现有 wiki 不会随 fork 自动部署 |

`analytics/worker/wrangler.jsonc` 带有作者现用的自定义域名、KV ID、D1 ID 和 R2 名称；必须换成公司资源。保留 `keep_vars: true`，不把密钥提交到仓库。

Dashboard 不止 HTML 中有默认 API 地址：`analytics/dashboard/public/src/api.js` 的 `productionApiBase` 和 `normalizeApiBase()` 对线上地址有归一化处理，也必须同步改，否则只改输入框仍可能回到作者服务。

Worker 的 `constants.js` 中还有作者 GitHub 仓库统计标识；插件同步和依赖安装包也需要真实内容、仓库权限或下载源。部署一个空 Worker 不能让全部功能自动可用。

所需密钥按用途区分，不要求此时提供任何明文值：Worker 的 `ADMIN_TOKEN`、`ACCOUNT_ID`、`ANALYTICS_API_TOKEN`、许可证私钥；构建侧的许可证私钥；部署侧 Cloudflare Token；发布镜像／R2 凭据。fork 不会复制原作者的这些凭据。

| 历史账户 | 不自动沿用原官方 Token、许可证、支付二维码缓存；作者账户余额不会因更名转到公司账户 |
| 用户自配 Key | 日常修改仍可通过设置完成；默认值变更不应无提示覆盖用户原有配置 |
| 本地日志 | 开发者模式保留完整 AI 日志的范围需纳入公司数据管理说明，且不应把日志目录当作统计事件正文 |
| 诊断源码副本 | `prepare-diagnosis-source.cjs` 从 HEAD 打包 client、sql、openxmlhelper 供 Agent 读取；公司版也会包含对应源码资料，不能误认 ASAR 或 EXE 是闭源保护 |

第一阶段无需为了品牌而重命名 `window.yibiao`、`yibiao-asset://`、`data-yb-*`、SQLite 既有文件名、Word 的 `YIBIAOTOC`／`YIBIAOANCHOR` 等内部协议。这些标识关联 IPC、插件、历史文件和导出助手，批量替换会扩大兼容风险。

## 10. 开源归属与公司文档

`LICENSE` 和 `NOTICE` 是必须保留并正确随分发提供的材料，不是品牌清理目标。`NOTICE` 明确列出作者、原始仓库、邮箱等，并要求修改版和对应源代码保留归属；可以同时添加公司的修改版权和维护说明。

需要分清：

- 公司内部运行或修改，与向外部客户分发安装包的义务不同。
- 向客户分发 AGPL 覆盖的修改程序时，需要安排与该程序版本对应的源码及构建相关材料；不能只给作者未修改的原始源码。
- 如果把修改后的受覆盖程序作为网络服务提供，需按 AGPL 的网络交互条款向相关用户提供对应源码获取机会。
- 自有品牌不等于可以删除原作者归属，也不等于取得所有第三方商标和素材的使用权。
- 打包配置的 `files` 没有显式列出根目录 LICENSE／NOTICE；应核实最终安装包的法律文件包含方式，必要时补充，不能假定依赖许可证清单替代项目 NOTICE。
- 依赖、Agent 工具、OCR 模型、字体、模板图片和外部插件各自的许可需整理第三方清单；本次未对每个二进制资源完成逐项许可审计。

公司隐私声明需要分别说明本地存储、模型请求、MinerU 解析、统计、许可证身份信息和故障诊断，不宜继续使用“我不会收集”这种个人维护者口吻。

## 11. 哪些可以配置，哪些需要重新打包

| 事项 | 当前实现下的方式 |
|---|---|
| 每个用户的第三方 Key、模型名、自定义 Base URL、并发 | 客户端设置保存到本地，无需重新打包 |
| 公告、更新日志、资源、广告、二维码、插件／依赖记录 | 由已部署的公司后台维护，无需每次打包客户端 |
| 产品名、Logo、应用 ID、默认服务地址、硬编码文档链接 | 需要修改代码／构建配置并重新打包 |
| 当前默认服务商与更新默认渠道 | 需要改默认配置；旧用户配置另做明确迁移策略 |
| 公司统一 Key 分发、账户计费、SSO | 当前没有通用后台开关直接完成，需服务端和客户端配套开发 |
| 更新包发布 | 无需重新改代码，但每个新客户端版本仍要构建并上传对应安装包和清单 |

建议在设计阶段增加一份公司产品配置，集中管理品牌显示、帮助链接、服务端入口、更新渠道和运营项目标识；Main、Renderer 和打包流程共用同一来源。具体文件位置、哪些字段允许服务端下发，待方案确认后实现。用户模型凭据仍沿用现有本地配置；公司共享密钥留在公司服务端。

## 12. 建议的实施顺序与交付物

| 阶段 | 范围 | 可验收交付物 |

如选择公司统一账户和计费，将其作为单独阶段接在已确认的模型方案后，不顺带扩充组织权限、云知识库等未提出的需求。

建议后续开发分支为 `codex/company-product`，基于 `13f239c7` 或开工时重新核实的 main 创建。不要将 8 月旧分支直接整体合并为公司基线；先比较旧目标字数实现与当前 main 已有字数控制，仅迁移确实仍需要的差异。本次尚未创建该分支。

## 13. 验收范围

| 检查 | 通过标准 |
|---|---|
| 静态外联检查 | 原作者运营域名只在必须保留的归属／历史文档或已确认合作入口中出现；运行时服务地址使用公司配置 |
| 实际外联记录 | 新装、启动、失败、更新、退出、模型测试、资源和插件操作逐项记录请求去向；不再有未确认的作者后台请求 |
| 真实标书流程 | 导入淮北小程序等真实样本，分析、目录、字数、事实、正文、商务填写、图片与 Word 导出走通 |
| 新 AI 调整 | 人工修改、小节补写、导出失败修复、取消与重启恢复均验证；启用限制清晰可见 |
| 模型配置 | 用户自定义服务可用；配置保存重启后保留；公司网关如选用则验证错误、余额和限流行为 |
| 安装与更新 | 公司版与原版身份符合方案；公司旧版能升级公司新版，未配置镜像时不会回退作者源 |
| 数据迁移 | 中文路径下迁移数据库、文件与会话；原版数据可回退；不混用原账户与公司账户 |
| 运营后台 | 公告、更新日志、二维码、资源、插件、依赖可维护；统计字段、聚合、趋势与看板等价保留 |
| 故障诊断 | 使用合成样本检查诊断内容、密钥脱敏、接收版本策略、保留期和访问控制，不拿真实客户文件做上传试验 |
| 断网与服务故障 | 启动、读取本地结果、授权提醒、后台失败不出现无法解释的退出或阻塞 |
| 法律与品牌材料 | LICENSE、NOTICE、公司修改说明、对应源码、第三方材料与安装包版本对应 |

实施后的基础检查遵循仓库要求：`client/` 下 `npm ci`、`npm run build`；改动的 Main 文件运行 `node --check`；SQLite／native 相关增加 Electron smoke；涉及窗口和 IPC 手工运行；依赖变更运行 `npm audit`。仅品牌分析文档不运行无关业务测试。
